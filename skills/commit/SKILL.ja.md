# Commit

独自の設定ファイルで定義されるコミット規則に沿って、[Conventional Commits v1.0.0](https://www.conventionalcommits.org/ja/v1.0.0/)に準拠したコミットを作成する。

コミット規約の初期化や設定ファイルの作成を求められた場合は、[初期化ガイド](references/init-guide.ja.md)に従って初期化作業を行う。
scopeの追加など、既存の規約の調整を求められた場合は、[設定リファレンス](references/configuration.ja.md)を参照して調整作業を行う。

## コミット手順

コミットは下記の手順に沿って行う。
スクリプトの実行時にエラーが発生した場合、特に指示がなければ、独断でフォールバックせず、ユーザーに報告した上で作業を中断すること。

### 1. コミットメッセージの記載ルールを確認する

下記コマンドを実行し、コミットメッセージの記載ルールを確認する。

```bash
uv run scripts/commit.py show-rules
```

以降、このコマンドの出力に従ってコミットメッセージを作成すること。
エラー発生時は下記の通りに対応する。

| エラー | 対応 |
| :-- | :-- |
| `uv`が見つからない（`command not found: uv`など） | [uv](https://docs.astral.sh/uv/)が必要な旨をユーザーに伝え、作業を中断する。自分でインストールしないこと。 |
| `error: no commit convention found ...` | [初期化ガイド](references/init-guide.ja.md)に従って初期化作業を行った後、次のステップへ進む。 |
| それ以外の設定エラー | [設定リファレンス](references/configuration.ja.md)を参照して設定の調整作業を行う。 |

### 2. コミット対象を確認する

コミット対象が指定されていない場合、下記の手順で対象を確定させる。

#### ステージされているファイルがある場合

ステージされているファイルをコミットして良いか、もし異なる場合はコミット対象となるファイルがどれかをユーザーに確認する。

#### ステージされているファイルがない場合

変更されているファイルが1つだけならば、そのファイルを追加してコミットするかどうかをユーザーに確認する。
それ以外の場合、コミット対象となるファイルがどれかをユーザーに確認する。

### 3. コミットの種別とスコープを確定する

コミット対象の差分とルールに基づいて、コミットの種別とスコープを決定する。

種別やスコープが絞りきれない場合は、一旦作業を中断してコミットの分割を提案すること。
その際、分割後のコミットそれぞれの種別、スコープ、内容について提示すること。
分割することに合意が得られた場合、ステップ4以降は分割後の各コミットに対して順番に行うこと。

### 4. コミットメッセージを作成・提案する

[コミット作成ガイド](references/creation-guide.ja.md)を読んだうえで、`--dry-run`を付けてコミットメッセージを作成する。

検証エラーが発生した場合は、修正して再試行すること。
拒否を回避するために`git commit`を直接呼んだり、規約自体を書き換えないこと。

### 5. 承認を得てコミットする

ステップ４で作成されたコミットメッセージをユーザーに提示し、その内容でコミットしてよいかを確認する。
ここで明確な承認が得られないままコミットを進めないこと。
もし、コミットメッセージに関する指摘を受けた場合、必ずステップ４からやり直すこと。
修正依頼は承認ではないため注意する。

承認を得たら、ステップ４で実行したコマンドから`--dry-run`を外して実行する。
amendなど、本書に記載のない操作が必要な場合は`uv run scripts/commit.py create --help`でオプションを確認する。
